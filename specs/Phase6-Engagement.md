**Timeline:** Weeks 44–51 (8 weeks)  
**Team:** Solo developer, LLM-assisted  
**Goal:** Transform raw analysis into an engaging daily habit through rich visualization, gamification, and multi-modal output that makes skin health actionable and motivating.

Phase 6 is where clinical accuracy meets user delight. The app now has a complete sensing pipeline (Phase 1–2), robust analysis (Phase 3), personalized recommendations (Phase 4), and adherence tools (Phase 5). This phase makes all of that *visible, tangible, and rewarding*.

## 1. Interactive 3D Face Map

### 1.1 Overview
The centerpiece of the Results screen. A rotatable 3D representation of the user's face with findings pinned at exact coordinates. Tapping a pin expands details: what it is, severity, root cause, treatment plan, timeline to improvement, and historical trend.

### 1.2 Geometry Source
- **Preferred:** LiDAR depth map (iPhone Pro) or photometric stereo reconstruction (Phase 1) → mesh with ~10k vertices
- **Fallback:** 2D textured projection onto canonical face model using MediaPipe 468 landmarks
- Store mesh as glTF 2.0 in SQLite BLOB or S3 (gzipped, ~50KB)

### 1.3 Layer System
User toggles visibility of findings by type:
- **All Concerns** (default): All active findings
- **Oiliness**: Sebum map heatmap overlay
- **Blood Flow**: Redness/inflammation zones
- **Texture**: Roughness/pore visibility
- **UV Damage**: Hyperpigmentation, sun spots
- **Bacterial**: Acne-prone zones with microbiome risk
- **3D Surface**: Pure geometry with lighting, no overlays

Each layer is a Fragment shader pass with configurable opacity. Layers are non-exclusive (user can enable multiple).

### 1.4 Finding Pins
- **Position:** Barycentric coordinates in mesh space (stored as `{faceId, u, v, w}`)
- **Visual:** 3D CSS-transformed billboard (always faces camera), color-coded by severity (green/yellow/orange/red)
- **Interaction:** Tap → expand card with:
  - Finding name and severity score
  - Root cause (e.g., "Dehydration + barrier impairment")
  - Active ingredients targeting it
  - Expected timeline (e.g., "Improvement in 4–6 weeks")
  - Trend sparkline (last 8 scans)
  - Quick action: "Add to Focus" or "Dismiss for now"

### 1.5 Zone Drill-Down
Tap cheek/forehead/nose/etc → filter findings to that zone, show product-to-zone mapping:
```
Left Cheek (3 concerns)
├─ Hyperpigmentation (moderate)
├─ Dehydration (mild)
└─ Fine lines (mild)

Targeted by:
• Vitamin C Serum (AM, Step 3)
• Niacinamide Moisturizer (AM/PM, Step 5)
```

### 1.6 Component API
```typescript
<FaceMap
  findings={findings} // FindingInstance[] with positions
  layers={['oiliness', 'uv']} // active layers
  mode="interactive" | "comparison" | "ar"
  onFindingTap={(finding) => navigation.navigate('FindingDetail', {finding})}
  meshSource={meshUri} // glTF or null for 2D fallback
  highlightZones={['leftCheek', 'forehead']} // optional
/>
```

### 1.7 Tech Stack
- **Rendering:** Three.js via `expo-three` (wraps expo-gl)
- **Mesh format:** glTF 2.0 with single Material
- **Shaders:** Custom fragment shaders for heatmaps (GLSL ES 3.0)
- **LOD:** High-poly mesh on iPhone 13+, simplified on older devices (detect via `Device.modelName`)
- **Gestures:** `react-native-gesture-handler` for pan/pinch/rotate

### 1.8 Performance
- Target 60 FPS on iPhone 12. Drop to 30 FPS on iPhone X.
- Lazy-load mesh on tab focus. Cache compiled shaders.
- Throttle gesture updates to 16ms.

## 2. Skin Health Score

### 2.1 Headline Metric
A single 0–100 score shown at top of Results screen. Calculated as weighted average of:
```
score = w₁·hydration + w₂·barrier + w₃·oilBalance + w₄·inflammation 
        + w₅·pigmentation + w₆·texture + w₇·microbiome
```

Weights are personalized based on user's primary concerns (from onboarding quiz). Default weights: `[0.2, 0.2, 0.15, 0.15, 0.1, 0.1, 0.1]`.

### 2.2 Trend Delta
Show change since last scan:
```
84 ↑3  (green, since last week)
```
Use signed integer with up/down arrow. Threshold for "significant change" is ±2 points (prevents noise).

### 2.3 Breakdown on Tap
Tap score → modal with bar chart showing contribution of each dimension:
```
Hydration        ████████░░ 82 (+5)
Barrier Health   ███████░░░ 78 (-1)
Oil Balance      █████████░ 91 (+2)
...
```

Show which factors improved, worsened, or stayed stable.

### 2.4 Benchmark (Opt-In)
"Your score is higher than 68% of users in your age group."  
Only show if user opts in during onboarding. Anonymized percentile from aggregated backend data.

## 5. Natural Language Report

### 5.1 Overview
Generated by Claude API for each scan. Explains findings in plain language, provides context, and suggests next steps. Reads like a dermatologist's notes.

### 5.2 Sections
1. **Summary** (2–3 sentences): High-level state of skin
2. **Key Concerns** (3–5 bullet points): What needs attention and why
3. **Routine Rationale** (paragraph): Why these products were chosen
4. **Phased Plan** (timeline): What to expect over next 12 weeks
5. **Confidence Notes** (transparency): Which findings are high-confidence vs. tentative

### 5.3 API Call
```typescript
const prompt = `
You are a dermatology AI assistant. Generate a report for this skin scan.

Scan Data:
${JSON.stringify(scanResult, null, 2)}

User Context:
- Age: ${user.age}, Skin Type: ${user.skinType}
- Primary Concerns: ${user.concerns.join(', ')}
- Routine Adherence: ${adherenceStats.weeklyRate}%

Guidelines:
- Be empathetic and encouraging
- Explain root causes, not just symptoms
- Use simple language (Flesch reading ease > 60)
- Keep total length under 500 words
- Every claim must reference scan data

Output as JSON matching ReportSection[] schema.
`;

const response = await anthropic.messages.create({
  model: 'claude-3-5-sonnet-20241022',
  max_tokens: 2000,
  temperature: 0.3,
  system: dermatologySystemPrompt,
  messages: [{role: 'user', content: prompt}]
});
```

### 5.4 Schema
```typescript
interface ReportSection {
  type: 'summary' | 'concerns' | 'routine' | 'timeline' | 'confidence';
  title: string;
  content: string; // Markdown allowed
  citations: string[]; // e.g., ["hydration_score", "sebum_zone_tzone"]
}
```

### 5.5 Verification Pipeline
Before showing to user:
1. Extract all numerical claims from report (regex + NLP)
2. Cross-check against `scanResult` fields
3. Flag hallucinations (claim with no supporting data)
4. If >2 hallucinations, regenerate with stricter prompt
5. Log discrepancies to backend for model fine-tuning

### 5.6 Caching
- Cache report per `scanId` in SQLite
- Regenerate if user edits concerns or routine changes significantly
- Bust cache after 30 days (in case model improves)

### 5.7 Fallback
If API call fails (network error, rate limit):
1. Show cached report from previous scan with banner: "Using last week's analysis"
2. Generate template report from local rules (non-LLM fallback)

## 6. Achievement System

### 6.1 Design Principles
- **Motivational, not punitive:** No shame for missed days
- **Clinical grounding:** Achievements tied to real skin health milestones
- **Intrinsic > extrinsic:** Focus on progress, not comparison

### 6.2 Achievement Types

#### Streak Achievements
- 3-day, 7-day, 30-day, 90-day, 180-day, 365-day streaks
- **No punishment:** If user misses a day, show "Welcome back! Your progress is still here." instead of "Streak broken."
- Visual: Flame icon that grows in size/intensity

#### Clinical Milestones
- "First Improvement" (any metric +5% vs baseline)
- "Hydration Hero" (hydration >80 for 3 consecutive scans)
- "Barrier Builder" (TEWL reduced by 20%)
- "Texture Smoother" (roughness decreased by 15%)
- "Consistent Caretaker" (90% adherence for 4 weeks)

#### Exploration Achievements
- "Full Scan" (complete all capture modes in one session)
- "Skin Scholar" (read 10 ingredient info pages)
- "Zone Master" (drill into all face zones)

### 6.3 Points System
Weekly points for:
- Logging routine (10 pts/day)
- Completing scan (50 pts)
- Hitting adherence target (bonus 100 pts)

Points are **purely motivational** – no unlocks or paywalls. Show weekly leaderboard of self only (no social comparison).

### 6.4 Badges
Visual: Illustrated icons (clean, medical-adjacent style). Unlock animation with haptic feedback and confetti.

Badges live in Profile tab under "Your Journey" section.

### 6.5 Shareable Progress Cards
"I've been taking care of my skin for 30 days!"  
Auto-generated image with:
- Achievement badge
- Key stat (e.g., "Hydration +12%")
- QR code to app download page (optional)

Share to Instagram Stories / Messages. No pressure to share.

### 6.6 Backend Schema
```sql

  type TEXT NOT NULL, -- 'streak' | 'milestone' | 'exploration'
  earned_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

);
```

## 7. Context-Aware Notifications

### 7.1 Overview
Smart, non-intrusive notifications that adapt to user behavior, environment, and skin context. Max 2 notifications per day.

### 7.2 Notification Types

#### Routine Reminders
- **Trigger:** User's self-reported AM/PM times (from Phase 5 routine calendar)
- **Smart timing:** Don't send PM reminder if user already logged PM routine
- **Personalization:** "Time for your Vitamin C serum!" (mentions specific product)

#### Weather-Triggered
- **Trigger:** UV index >6 or humidity <30%
- **Content:** "High UV today – don't skip your SPF 50."
- **Frequency:** Max 1/week to avoid annoyance

#### Health Data Integration
- **iOS HealthKit:** Detect cycle phase (luteal → increase barrier support reminder)
- **Sleep data:** Poor sleep detected → "Your skin repairs during sleep. Prioritize rest tonight."

#### Encouragement
- **Trigger:** 5 days of perfect adherence
- **Content:** "You're on fire! Your skin is thanking you."
- **Tone:** Warm, never condescending

#### Restock Alerts
- **Trigger:** Product usage model predicts empty in 7 days
- **Content:** "Your CeraVe Hydrating Cleanser is running low. Order now?"
- **CTA:** Deep link to product or shopping list

### 7.3 Notification Service Architecture

Built as separate NestJS module: `NotificationService`.

#### Input Events
1. `RoutineScheduled` (from Phase 5 calendar)
2. `ScanCompleted` (from Phase 3 analysis)
3. `WeatherUpdate` (from external API)
4. `HealthDataSync` (from HealthKit/Google Fit)
5. `AchievementEarned` (from achievement system)

#### Priority Ranking
Each notification has priority score (0–100):
```typescript
const priority = 
  baseScore +
  (timeSensitive ? 20 : 0) +
  (actionable ? 15 : 0) +
  (personalized ? 10 : 0) -
  (userMutedCategory ? 50 : 0);
```

Only top 2 priorities per day are sent.

#### Bundling
If >2 pending notifications, bundle into one:
```
Skin Update
• Time for your PM routine
• Your hydration improved by 8%
• Achievement unlocked: 7-day streak
```

#### Learned Timing
Track when user opens notifications. If 80% of opens happen 7–9pm, shift all routine reminders to that window.

#### Mute Mode
User can enable "Quiet Mode" (no notifications except critical restock alerts).

### 7.4 Backend Schema
```sql
CREATE TABLE notification_queue (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  type TEXT NOT NULL,
  priority INTEGER DEFAULT 50,
  scheduled_for TIMESTAMP,
  sent_at TIMESTAMP,
  opened_at TIMESTAMP,
  content JSONB
);

CREATE TABLE notification_preferences (
  user_id TEXT PRIMARY KEY,
  routine_reminders BOOLEAN DEFAULT true,
  weather_alerts BOOLEAN DEFAULT true,
  encouragement BOOLEAN DEFAULT true,
  restock_alerts BOOLEAN DEFAULT true,
  quiet_mode BOOLEAN DEFAULT false,
  learned_send_time TIME -- e.g., '19:30:00'
);
```

### 7.5 Delivery
- **iOS:** APNs with rich notification (thumbnail image, action buttons)
- **Android:** FCM with BigPictureStyle

### 8.2 Content

- **Trends:** "Your hydration improved, but oiliness increased slightly."
- **Adherence:** "You logged your routine 6 out of 7 days (86%)"
- **Timeline Context:** "You're in week 4 of your hyperpigmentation treatment."
- **One Action:** "This week, focus on consistency with your retinoid."

### 8.3 Rich Notification
Include sparkline chart as image attachment (generated server-side):
```
Score: 84 ↑3
Adherence: 86%
[Sparkline image: 7-day score trend]
```

Tap notification → opens Weekly Summary screen in app.

### 8.4 Backend Job
Cron job runs every Sunday 9am per user's timezone:
```typescript
@Cron('0 9 * * 0') // Every Sunday at 9am
async sendWeeklyDigest() {
  const users = await this.userRepo.findAllActive();
  for (const user of users) {
    const summary = await this.generateWeeklySummary(user.id);
    await this.notificationService.send({
      userId: user.id,
      type: 'weekly_digest',
      content: summary,
    });
  }
}
```

## 13. Onboarding Polish

### 13.1 Progressive Disclosure
Don't dump all features in first session. Introduce gradually:
- **First scan:** Just show score and top 3 findings
- **Second scan:** Reveal before/after slider
- **Third scan:** Unlock 3D face map
- **Week 2:** Introduce achievements
- **Week 4:** Show AR overlay option

### 13.2 Emotional Design
- **Language:** Warm, empathetic, non-judgmental
  - ✅ "Your skin is unique, and we're here to help."
  - ❌ "Your skin has severe issues."
- **Visuals:** Soft gradients, rounded corners, nature-inspired colors
- **Micro-interactions:** Smooth animations, delightful transitions

### 13.3 First-Scan Walkthrough
After very first scan completes:
1. Animated highlight: "This is your Skin Health Score."
2. Swipe to findings: "These are your primary concerns. Tap to learn more."
3. Swipe to routine: "We've built a personalized routine for you."
4. Final screen: "You're all set! Complete your first routine to start tracking progress."

Skippable at any point.

### 13.4 Information Hierarchy
Design every screen with 4 levels:
1. **Glance** (<1 sec): Headline metric (e.g., score)
2. **Scan** (3–5 sec): Key trends and CTAs
3. **Read** (15–30 sec): Detailed findings and explanations
4. **Explore** (>1 min): Drill-downs, diary, settings

Most users never go beyond level 2. Design for that.

## 14. Notification Service Architecture

### 14.1 Module Structure
```
backend/src/notification/
├── notification.module.ts
├── notification.service.ts (orchestrator)
├── notification.controller.ts (manual triggers for testing)
├── strategies/
│   ├── routine-reminder.strategy.ts
│   ├── weather-alert.strategy.ts
│   ├── achievement.strategy.ts
│   └── weekly-digest.strategy.ts
├── priority.service.ts (ranking and budgeting)
└── delivery.service.ts (APNs/FCM abstraction)
```

### 14.2 Event-Driven Flow
1. Producer emits event (e.g., `ScanCompleted`, `RoutineScheduled`)
2. `NotificationService` listens via event bus
3. Calls appropriate strategy to generate notification payload
4. `PriorityService` assigns score and checks budget (max 2/day)
5. `DeliveryService` sends via APNs/FCM
6. Log to `notification_queue` table

### 14.3 Strategy Pattern
Each notification type implements `NotificationStrategy` interface:
```typescript
interface NotificationStrategy {
  shouldTrigger(event: Event, user: User): Promise<boolean>;
  generatePayload(event: Event, user: User): Promise<NotificationPayload>;
  getPriority(event: Event, user: User): number;
}
```

Example: `RoutineReminderStrategy`:
```typescript
async shouldTrigger(event: RoutineScheduledEvent, user: User): Promise<boolean> {
  const alreadyLogged = await this.routineRepo.findTodayLog(user.id, event.timeOfDay);
  const isWithinWindow = isWithin30Minutes(event.scheduledTime, now());
  return !alreadyLogged && isWithinWindow;
}

async generatePayload(event: RoutineScheduledEvent, user: User): Promise<NotificationPayload> {
  const nextProduct = event.routine.steps[0].product.name;
  return {
    title: 'Skincare Time',
    body: `Time for your ${nextProduct}!`,
    data: {routineId: event.routine.id},
  };
}

getPriority(event: RoutineScheduledEvent, user: User): number {
  return 70; // High priority for routine adherence
}
```

### 14.4 Priority Budgeting
```typescript
async scheduleNotification(payload: NotificationPayload, priority: number) {
  const todayCount = await this.countTodayNotifications(payload.userId);
  if (todayCount >= 2) {
    const lowestToday = await this.getLowestPriorityToday(payload.userId);
    if (priority > lowestToday.priority) {
      await this.cancelNotification(lowestToday.id);
      await this.sendNotification(payload);
    } else {
      await this.queueForTomorrow(payload);
    }
  } else {
    await this.sendNotification(payload);
  }
}
```

### 14.5 Learned Timing
Track open rates per hour:
```sql
SELECT 
  EXTRACT(HOUR FROM opened_at) as hour,
  COUNT(*) as open_count
FROM notification_queue
WHERE user_id = ? AND opened_at IS NOT NULL
GROUP BY hour
ORDER BY open_count DESC
LIMIT 1;
```

## 15. LLM Report Integration

### 15.1 API Configuration
```typescript
// backend/src/llm/anthropic.service.ts
import Anthropic from '@anthropic-ai/sdk';

@Injectable()
export class AnthropicService {
  private client: Anthropic;

  constructor(private configService: ConfigService) {
    this.client = new Anthropic({
      apiKey: configService.get('ANTHROPIC_API_KEY'),
    });
  }

  async generateReport(
    scanResult: ScanResult, 
    userContext: UserContext
  ): Promise<ReportSection[]> {
    const prompt = this.buildPrompt(scanResult, userContext);
    
    const response = await this.client.messages.create({
      model: 'claude-3-5-sonnet-20241022',
      max_tokens: 2000,
      temperature: 0.3,
      system: DERMATOLOGY_SYSTEM_PROMPT,
      messages: [{role: 'user', content: prompt}],
    });

    const rawReport = response.content[0].text;
    const sections = JSON.parse(rawReport) as ReportSection[];
    
    // Verification pipeline
    const verified = await this.verifyCitations(sections, scanResult);
    if (!verified.valid) {
      throw new Error(`Report hallucination detected: ${verified.errors.join(', ')}`);
    }

    return sections;
  }
}
```

### 15.4 Verification Pipeline
```typescript
async verifyCitations(
  sections: ReportSection[], 
  scanResult: ScanResult
): Promise<{valid: boolean; errors: string[]}> {
  const errors: string[] = [];

  for (const section of sections) {
    for (const citation of section.citations) {
      // Check if citation exists in scan data
      const value = _.get(scanResult, citation);
      if (value === undefined) {
        errors.push(`Invalid citation: ${citation}`);
      }

      // Extract numerical claims from content
      const claims = extractNumericalClaims(section.content);
      for (const claim of claims) {
        if (!isConsistentWithScanData(claim, scanResult)) {
          errors.push(`Inconsistent claim: "${claim}"`);
        }
      }
    }
  }

  return {valid: errors.length === 0, errors};
}
```

### 15.6 Retry Logic
```typescript
async generateReportWithRetry(
  scanResult: ScanResult,
  userContext: UserContext,
  maxRetries = 3
): Promise<ReportSection[]> {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      const report = await this.generateReport(scanResult, userContext);
      const verified = await this.verifyCitations(report, scanResult);
      
      if (verified.valid) {
        return report;
      } else {
        console.warn(`Verification failed on attempt ${attempt + 1}:`, verified.errors);
      }
    } catch (error) {
      console.error(`API call failed on attempt ${attempt + 1}:`, error);
      await sleep(2 ** attempt * 1000); // Exponential backoff
    }
  }

  throw new Error('Failed to generate valid report after max retries');
}
```
